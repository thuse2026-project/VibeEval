# 样题维护与验证

本目录仅供维护者使用，不属于考生工程。

## 验证原始版本与参考修复

需要 Python 3.12。在仓库根目录运行：

```powershell
python maintainer/python-debug-01/verify_sample.py
```

脚本先将考生工程复制到两个临时目录，在其中分别执行原始版和参考版的测试，并检查：

- 原始版共运行 8 项，恰好只有首尾相接与取消释放两项失败，错误、跳过和预期失败标记均为 0。
- 临时参考版仅替换 `src/booking.py`，同一套 8 项公开测试全部通过。
- 原始目录的文件集合和内容摘要在运行前后保持一致。正常结束后自动清理临时目录。

全部符合时脚本退出码为 0；缺文件、额外失败、失败测试名不符或参考修复不通过时返回非零。它用于发布前验证未修改的样题模板，不是候选人评分器；考生修复后的工程或新增测试不应套用“必须 8 项且失败两项”的模板检查。

`reference/booking.py` 是维护者参考实现：冲突判断忽略已取消预约，并使用严格的时间区间交叉判断。考生可以采用其他满足相同接口和行为的实现。

## 发布边界

- 考生材料仅取 `problems/python-debug-01/`，包含 README、依赖声明、`src/` 和 `tests/`；不挂载整个仓库。
- 本目录、BCL、平台源码和其他维护材料均不进入考生沙箱或答卷快照。目录分离是发布约定，实际挂载仍需沙箱负责人按边界执行。
- 平台自身检查继续运行 `backend/tests/`；不要把故意失败的考生测试当成平台回归失败。CI 若验证此样题，应执行上面的维护者脚本。
- 当前没有隐藏测试、打分器或自动检查考生新增测试质量的功能；新增回归测试由考官查看。

## 人工体验

先在考生目录运行演示和测试，确认问题可复现。若要亲自尝试修复，请将该目录复制到仓库之外再作答，保留仓库中的原始缺陷版本作为发布模板。
