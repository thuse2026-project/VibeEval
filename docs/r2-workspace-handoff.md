## 这轮工作台改动

- 两道代码题共用 R1 的工作台布局。顶部固定题名、倒计时、保存状态和提交。文件与题面各有页签，Agent 位于右侧。
- 文件区支持目录展开和按路径筛选。切换到已保存文件时重新读取服务器版本。未保存的草稿留在编辑器，手动重新读取前提示。
- 代码改动在 5 秒后使用既有队列保存，交卷前保存待写文件。阶段说明随提交封存。
- 终端折叠时保留 WebSocket 和输出，展开重新适配尺寸。每个代码阶段连接自己的终端。

## 下一轮需要对齐

1. **yellow 主接整场前端。** 以 v2 状态、环节 ID、权限列表和 Unix 秒为准。复用代码阶段工作台，补阶段一的探索与独立答题、阶段二的缺陷报告、草稿恢复、阶段过渡和考官侧阶段视图。
2. **alt 补平台级接口。** 落实阶段累计 Agent 用量与耗尽提示。提供阶段答卷和评分记录的考官接口，明确后台评分、重评和发布的状态。
3. **共同验收 Agent 操作。** 真实模型读、改、跑测试，审批前后的差异、错误恢复和刷新后继续。尤其验证阶段结束时模型请求和命令停止、文件不能再改、下一题文件和对话独立。
4. **组长试做和评审。** 用同一套样卷检查两道代码题的分值、证据和难度。待整场流程稳定，再按仓库规范提交 PR 交叉复查。
