## 给赵晨一：一个只读 reader 接两处

权威接口在 [api.md](api.md) 的“答卷详情与提交服务只读契约”。模型和接入函数位于 `backend/app/admin/submissions.py`。

- `list_submissions()` 返回每个考生每个场次的一条已提交摘要；历史记录无需一定出现在本地入场表中。
- `get_submission(id)` 返回固定快照与公开测试原始输出，查无记录返回 None；不返回活动沙箱文件。
- 注入 `get_submission_reader` 后，总览和详情同时生效，接入标志自动生成；不必分别改两个路由或另建管理端数据库。
- 正常数据使用同一提交编号、身份、时间和快照引用；不含内部磁盘路径或凭证。公开测试输出的 null 与空字符串语义不同，见 API。
- 当前没有 reader 时，真实总览只展示入场记录，真实详情返回明确的 503；演示数据始终单独选择。

本地考官账号使用哈希文件、考官会话使用单进程内存、入场使用隔离的 SQLite。这些是本地开发实现，未创建 PostgreSQL 模型或迁移。数据库字段和迁移由你统一维护，后续接入应保持当前 HTTP 行为及原子一次性消费/恢复语义。

## 给刘婧瑶和陈弘毅

- 正式候选人工作台尚未实现，`/entry` 仅是入场与恢复验证页面，后续可直接调用相同 API。
- 入场成功状态为 `admitted`，`started_at`、`deadline_at` 都是 null。沙箱真正就绪并由考生确认开始后才计时，不能将已入场显示成已开始。
- `session_id` 只定位会话，Cookie 才是当前浏览器恢复凭证；后续文件接口复用现有归属检查并补上工作区状态限制。
- WebSocket 浏览器不能像 HTTP fetch 一样任意添加自定义请求头，因此 PTY 鉴权需要单独对齐 Cookie/Origin，不能直接照搬 HTTP 来源头要求。
- 样题运行 Python 3.12，只用标准库。公开测试原始故意失败两项；参考修复、验证脚本绝不能随考生材料挂载。
- 交卷和快照保存归赵晨一，沙箱停止写入与冻结配合归陈弘毅；本次未新增 submit 路由或后台任务。
