## 演示前准备

1. 确认私有服务和本机 SSH 转发可用；原本机入口为 `http://127.0.0.1:5182/entry?mode=r2`，考官为 `/admin/r2`。这是本机转发地址，不是给他人直接打开的公网链接。
2. 准备一份新考生凭证。已交卷的旧凭证不能重新开始，勿现场临时重置旧答卷。凭证生成方法见 [后端验收准备](datasette-agent-backend-acceptance.md)。凭证、密码和 Key 不写入本文。
3. 提前打开一份真实已交卷答卷作为备用，核对当前规则客观分已出、人工分仍可为未评。
4. 现场以现成记录串讲为主，实时 Agent 只演示短操作。若模型慢，切换历史对话/已交卷记录，不反复点击发送。

## 可复制的实时短提示

只需要展示 Agent 能看到工作区时，用这条，不做全仓探索：

```text
请只读取当前项目根目录的 README.md。用三句话说明任务目标、允许修改的文件和测试命令。暂时不要读其他文件、不要运行命令，也不要修改代码。
```

若 20–30 秒还没返回，说明“这里是实际模型请求”，切到已保存的真实对话继续讲解即可。不要把截图、历史记录或预录结果说成刚刚实时生成。

## 完整复跑提示（留给后续人工验收，不必现场全做）

每道题使用新工作区、同题同一对话；只批准本次目标对应的操作。始终使用 README 原命令，不修改公开测试来制造通过。

第一步：

```text
请先读根目录 README.md，再看 tests/test_public.py 和题目相关的代码片段。解释公开测试检查什么、准备先修改哪里。先给简短计划，不运行命令、不修改文件，不要遍历全仓。
```

第二步：

```text
现在只运行 README 的公开测试命令，直接执行，不追加 echo 或其它掩盖退出码的命令。不改文件。告诉我真实的测试名称、失败原因和退出码。
```

预期：业务拓展原始 1 项失败；历史 Bug 原始 2 项失败。导入错误、环境错误不是这个预期。

第三步（业务拓展）：

```text
根据 README 和实际失败，只修改 datasette/views/table.py，补齐列统计需要的数据。保留公开测试和 tests/test_candidate.py。请提出实际修改供我审批，应用后运行同一条测试命令；若失败就继续修复。最后简短列出修改、真实结果和未验证的边界。
```

第三步（历史 Bug）：

```text
根据 README 和两个实际失败修复计数与切换链接问题。只修改 datasette/facets.py、datasette/views/table.py、datasette/views/table_extras.py 中确有必要的文件，保留两个测试文件。提出实际修改供我审批，再运行同一条测试命令。报告真实结果、退出码和剩余问题。
```

第四步（两题通用，补新增测试）：

```text
请在 tests/test_candidate.py 补充一个有价值的回归或边界测试，不能只是复制或改名公开测试。先解释它多检查了什么、预期为何正确，再提出修改审批。运行全部测试，准确报告失败原因；不要为了让测试通过而删减正确断言。
```

第五步：核对保存状态，填写“实际改动、已运行验证、未验证内容”，手动提交。转到考官查看固定答卷，执行客观评测和新增测试对照，再按细则给分。
