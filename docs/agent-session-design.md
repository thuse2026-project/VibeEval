## 本分支交付六部分

### 1. 单次模型 API 与全局配置

- 复用现有后端 Key、基础地址、默认模型、超时和输出上限配置。
- 支持普通文本和原生工具调用的请求/响应；保留工具调用 ID。
- 全局 Agent prompt 与工具 schema 有明确版本，请求可查看实际采用的版本和内容。
- 统一返回文本、工具请求、结束原因、模型标识和实际用量；错误与截断显式返回。
- 只做一次模型调用，不隐式执行工具、不自动重试或连续运行到结束。

### 2. 会话历史与当前模型上下文

- 稳定的 Conversation ID 和调用方提供的可信归属范围。
- 保存用户消息、助手消息、工具请求、工具结果和整轮结束/中断记录。
- 从同一记录生成用户视图和模型输入，不允许前端用 messages 覆盖服务端完整历史。
- 当前 API 上下文可以由压缩检查点和后续完整交换重建；完整记录按外层存储策略保留。
- 可序列化快照，提供存储适配接口；默认实现先支持内存与导出/导入，不绑定业务数据库。

### 3. Turn 与模型步骤的维护

- 一个用户轮次可以包含多次模型调用和多批工具结果。
- 同一会话一次处理一个用户轮次；新输入排队与调度由上层决定。
- 单独记录当前模型步骤 ID、待回传的工具调用、结束原因和本轮用量。
- 正常状态：准备调用 → 等待模型 → 等待外部工具结果 → 准备下一次调用 → 完成。
- 异常状态：模型失败、格式无效、工具失败、用户中断；不把普通助手说明直接当作整轮完成。
- 重复提交不重复累计结果或用量；过期步骤和错误调用 ID 不能改写当前轮次。

这只是 API 交互状态，不引入新的任务调度框架、审批状态机或后台执行系统。

### 4. 原生工具调用与外部结果回传

- 工具注册接口接收名称、说明和参数 schema；模型看到的是 tools 定义。
- 模型返回 tool call 后，库解析名称、参数和调用 ID，向外层返回 ToolRequest。
- 外层交回 ToolResult，库匹配、记录，并准备下一次模型请求。
- 多个工具请求允许分批交回；结果齐全后才能继续该步骤。
- 失败与拒绝也用明确的错误结果表达；取消后不自动重启工具。
- 不把自然语言代码块当作命令，不要求每次回答都包成自定义 actions JSON。

文件、代码段、代码库、其他会话和题目历史，先作为具体读取工具的输入/结果。
这层维护读取交互的消息关系。实际读取来源、鉴权、命令执行、补丁应用由外层负责。
我们自己的会话历史可由会话读取接口提供，题目历史可作为初始材料或读取结果导入。

### 5. 上下文长度与压缩

- 保留历史记录与当前模型窗口的区别，暴露用量和上下文不足信息。
- 提供显式压缩调用与采用压缩结果的接口；不偷偷增加模型调用。
- 压缩后的模型窗口与原始记录都能保存和恢复。
- 保留工具交换的配对，不在等待工具结果的中途截断一半调用链。
- 被压缩或移出窗口的材料，需要时通过工具重新读取，不假定模型仍持有完整正文。

首版不设计逐资源阅读覆盖率、自动补读、跨版本区间合并或智能缓存淘汰。

### 6. 上下游接口与验证

面向上游的能力：

| 接口能力 | 返回的东西 |
| --- | --- |
| 创建、读取会话 | 会话 ID、历史和当前状态 |
| 提交用户消息 | 本轮标识和更新后的状态 |
| 准备/查看下一次请求 | 实际 messages、tools、模型参数与配置版本，不含 Key |
| 推进一次模型步骤 | 助手输出、工具请求或整轮结束状态 |
| 提交工具结果 | 结果是否被接受、是否还在等待其他工具 |
| 中断当前轮次 | 已中断状态及未完成调用清单 |
| 显式压缩、导出、恢复 | 压缩结果或可恢复快照 |

面向下游只要求三个边界：CompletionClient（单次模型调用）、SessionStore（加载/按版本保存会话）、
工具请求/结果端口（向外暴露请求并接回结果）。不绑定数据库、沙箱、HTTP 或前端组件。

首次实现按非流式完整模型响应处理；返回结构保留消息/步骤事件，流式网络接入后续再做。
reasoning_summary 如有，仅为简短可展示说明；不要求模型提供内部推理轨迹。
供应商续调必需的额外字段由适配器保存，不提升为普通用户消息。

## 暂不做的事

- 独立的统一资源注册库、引用权限系统、已读行号/消息区间账本。
- 文件读取与执行的具体环境接入、命令执行器、代码修改与审批流程。
- 自主执行循环、后台任务调度、多 Agent、会话分叉和回滚文件。
- 新的数据库迁移、前端页面、正式部署，以及流式网络通道。

## 分批顺序与验收

1. 会话、轮次、消息、工具结果的数据结构与存储接口；先用手动结果验证状态。
2. 原生工具调用的模型适配、全局 prompt 与请求预览；验证读取请求 → 外部结果 → 回答。
3. 历史恢复、模型上下文重建、显式压缩及用量；验证长对话续接。
4. 接口说明和组员接入示例；只使用假工具或外层提供的工具结果。

每批检查后等待用户确认，再提交并继续。分支完成标准：多轮对话保留历史，工具结果正确配对，
中断后不会误续跑，压缩与恢复不破坏消息链，上下游可各自替换且无需实际沙箱执行器。
