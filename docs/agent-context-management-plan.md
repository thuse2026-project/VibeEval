# Agent 上下文、文件阅读记录与跨对话阅读

状态：2026-11-06 用户已确认设计与验收范围，按批实现。本文不表示所有能力已经实现。
上下文管理是本分支的核心职责，需要贯穿原子阅读、模型循环、执行结果、数据库和恢复。
本分支只做后端，前端消费查询与事件接口。

## 1. 四类状态分开维护

| 层 | 内容与作用 |
| --- | --- |
| 完整历史 | 原始用户输入、引用、模型输出、工具请求、真实结果、批准/提问与运行状态，作为可追溯记录 |
| 材料与阅读记录 | 取得过哪些文件/消息/输出，来源、版本、实际区间、内容摘要及对应不可变材料 |
| 当前模型窗口 | 这次真正发送的系统说明、当前任务、近期交换、正文片段、摘要和定位信息 |
| 压缩检查点 | 摘要、覆盖边界、材料关联、保留项目、代数、来源摘要和实际用量，支持继续运行与恢复 |

“文件被引用过”“某段正文返回过”“正文现在还在模型窗口”是三个不同事实。
完整记录和材料持久保存，压缩只改变模型窗口投影；不通过删除数据库历史节省模型 token。
同一考试的材料可以按权限复用快照，不意味着不同 Conversation 自动共享模型记忆。

## 2. Agent 读过的文件怎样管理

每一次实际阅读形成 ReadObservation，至少关联：

- exam_session_id、conversation_id、turn_id、step_id、tool_call_id。
- 来源类型、来源 ID、workspace/path，或者源对话/执行 ID。
- 读取时版本、源内容摘要、实际返回范围、材料摘要与 material_id。
- 是否完整、是否截断、还有多少/怎样继续读取、读取时间。

MaterialSnapshot 保存实际取材内容；只阅读片段时不把它标为整文件已读。
目录、文件名匹配和文本搜索只记录目录/命中信息，不假定已读所有命中文件。
阅读记录用于定位和取回材料，不作为“模型理解过代码”的证明。

对文件变化和重复阅读采用以下规则：

1. 同文件同版本的重复片段可以复用材料存储，在当前窗口中控制正文重复。
2. 只有正文实际仍在窗口时，才可用明确的重复材料标记替代旧副本，并保留原工具调用配对。
3. 正文移出窗口或已被摘要后，需要时通过 material_id 或原文件重新读取，不能只返回“以前读过”。
4. 文件版本变化时保留原阅读快照，新版本重新形成记录；不同版本的行区间不能合并。
5. 对未观察到的终端/后台写入不宣称已知最新版本；重新阅读时核对实际内容，写入前再次核对版本/摘要。
6. 未保存选区是独立缓冲区材料，不能标为实际沙箱文件；中文、emoji、换行和列编码需要测试。

当前模型请求生成 ContextManifest，记录每项材料是正文、片段、摘要、定位信息或未进入窗口。
对外可查询阅读清单和当前窗口包含情况，避免依赖前端猜测“Agent 现在还能看到什么”。
不静默把工具结果改为空；去重/外置后的内容有明确说明和可读取来源，原始结果仍可追溯。

## 3. 跨对话怎样查询与阅读

提供独立原子接口，例如 list_conversations、read_conversation_summary、read_conversation_messages、
read_conversation_tool_result；用户附加另一会话引用与 Agent 真正读取该会话仍是两种操作。

访问范围由服务端考试归属和来源策略决定：默认同一考生本次考试的对话，以及题目开放的历史。
不因知道 conversation_id 就取得权限，也不把别人的消息当作本轮用户指令。

读取结果包含源 conversation_id、源 revision、turn/step/message 范围、材料 ID、
实际消息/摘要/结果和分页信息。读取活动会话时也标明其状态与观察时间，不伪装成已完成记录。
分页固定来源版本；能取得原阅读快照时继续使用，无法重现时明确返回版本变化，不拼接不同版本冒充一个快照。

源对话的系统提示、鉴权数据和供应商内部续调字段不作为公开阅读结果。
源消息以 tool result 材料进入当前 Conversation，不合并两条会话状态，也不继承源会话的权限。
当前会话保存这次跨会话阅读记录；压缩时继续保留来源版本、要点和材料定位，之后可再次取回原文。

## 4. 主动压缩

这里将主动压缩定义为：用户/API 显式请求，或 Agent 通过明确的压缩请求主动提出。
调用方可以查看预计覆盖范围、当前窗口、输出预算和实际压缩结果。

压缩流程仍拆为准备、调用、采用三个环节；采用按来源边界和 revision 校验，并记录用量。
主动请求可以安排到安全边界执行；不能切开未完成工具交换或丢掉等待中的批准/提问。
压缩失败、输出不完整或采用时来源已变化，不替换原窗口。

## 5. 被动压缩与超限补救

这里将被动压缩定义为服务端自动维护：

- 每次模型请求前评估当前窗口预算，达到软阈值时触发。
- 大文件/命令输出按工具结果预算外置或提供有来源的片段，不让单个结果无限占用窗口。
- 若供应商明确返回上下文超限，允许一次有记录的压缩补救和重新准备；普通网络故障不因此重试。

处理顺序为：整理重复与大型材料 → 保留必要近期交换 → 摘要历史 → 重新评估窗口。
具体阈值由模型窗口、输出预留和安全余量配置；精确 token 计数不可用时明确标记估计方式，
不把字符数宣称为精确 token。压缩本身的上下文、输出和调用成本也计入运行预算。

必要保护项包括：当前用户请求、硬约束、已确认决定、未完成计划、用户已答信息、
等待中的操作/批准/提问、近期完整工具交换、关键文件版本以及错误和未知执行状态。
最新返回但模型尚未消费的工具结果不能被静默清掉；太大时提供有来源的受控预览和继续读取方式。

## 6. 一轮很长时也要能压缩

现有核心只支持空闲时、按完整 Turn 前缀显式压缩，这是本分支需要补齐的限制。
新的覆盖边界需支持已结束 Turn，以及活动 Turn 内已经完成的模型/工具交换。

活动 Turn 的当前用户请求单独保护，未完成的工具请求/结果链保留完整；
旧的已完成步骤可以转成摘要和材料定位，允许同一轮继续运行，不要求结束或中断该轮才能压缩。
检查点绑定已覆盖内容的稳定标识与摘要，不能仅以“前几条消息”表达边界。
并发新增结果使摘要过期时，旧结果不覆盖新状态；自动维护有次数和成本上限。

摘要至少覆盖：任务目标、约束、计划与决定、已完成操作及执行 ID、失败/未知状态、
待办，以及关键文件/跨会话材料的版本、范围、要点与取回位置。
摘要作为历史数据，不提升为系统权限，也不要求模型输出内部推理。
确实无法缩到预算内时返回明确的容量错误和可选处理方式，不无限压缩或静默丢弃关键任务。

## 7. 数据库、恢复与对外接口

持久记录至少包括 InputReference、ReadObservation、MaterialSnapshot、ContextCheckpoint、
每次模型请求的 ContextManifest，以及每次压缩的触发来源、请求、结果和用量。
会话完整历史、材料快照与压缩窗口可在进程重启后核对重建。
模型窗口恢复不是恢复文件系统；文件变更检查点与上下文检查点分开。

对外提供：

- 当前窗口预算/估计方式、压缩代数、保留边界和材料清单查询。
- 用户引用、阅读清单、指定版本材料取回与跨会话阅读接口。
- 显式压缩请求、任务状态，以及自动压缩开始/成功/采用/失败事件。
- 每次工具操作的 allow/ask/deny 与执行状态，包括等待批准、运行、失败和未知结果。

前端只消费这些接口，不承担上下文裁剪、摘要拼装、模型续调或执行回执生成。

## 9. 重点验收

1. 重复读取同版本文件后，完整历史仍在，当前窗口没有无意义的正文累积。
2. 文件在读取后被终端修改，旧阅读快照可查，新读取和写入能识别新版本。
3. 目录、搜索命中、局部阅读、截断阅读与全文阅读不会混淆。
4. 多轮长对话和单轮大量工具调用都可自动压缩，并继续完成任务。
5. 等待批准/提问或有未完成工具链时，不丢失操作、绑定参数或批准状态。
6. 压缩后能按材料 ID 重读旧代码/输出，当前用户目标、决定和关键文件版本仍在。
7. 跨会话读取有真实权限、来源版本、稳定分页和目标会话中的阅读记录。
8. 压缩失败、摘要截断、并发版本变化、超限补救均有明确回执；原窗口不被坏结果覆盖。
9. 重启后恢复相同窗口与材料关系，所有压缩调用和模型用量能核对。
