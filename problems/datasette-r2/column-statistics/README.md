# 为数据表补齐列统计

你接手了一个 Datasette 数据浏览项目。表格页面已经有列统计弹窗和用于运行查询的入口，但打开表格时拿不到弹窗所需的数据。请补齐表格页面的后端逻辑。

- 允许执行自定义 SQL 的用户，在表格页面可以打开列统计。统计使用当前筛选后的全部匹配行，翻页、排序或隐藏列不应缩小统计范围。
- 页面传给现有弹窗的数据放在 `window._datasetteTableData.executeSql`。其中 `queryUrl` 和 `editorUrl` 指向现有查询入口，并遵循站点的路径前缀。
- `columns` 按表结构顺序提供 `name` 和小写声明类型 `type`。无主键普通表含其可用的 `rowid`，页面上隐藏的普通列仍可统计。SQLite 的隐藏虚拟表内部列不应出现，可查询的生成列应保留。
- 有业务筛选时，提供 `filter`，包含 SQL 条件 `where`、参数 `params` 和描述 `description`。条件与绑定参数不包含分页游标。保留参数的原始数值或文本类型。未筛选时省略 `filter`。参数无法安全表示为 JSON 时，省略 `executeSql`。
- 已有查询权限规则继续有效。无执行 SQL 权限的用户仍能浏览允许访问的表格，但页面不提供统计入口和相应数据。已有表格、查询页面、导出和分页行为继续工作。

允许修改 `datasette/views/table.py` 和 `tests/test_candidate.py`。弹窗、SQL 入口和测试数据可直接复用。公开测试执行：

```sh
python -m unittest discover -s tests -p "test_*.py" -v
```

提交代码和一段实现说明，写明你如何核对统计口径与兼容性。功能测试 50 分，既有行为 20 分，新增测试 15 分，实现质量 15 分。
